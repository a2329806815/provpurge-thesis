# ProvPurge 论文开题定案汇总

截至 2026-10-30。本文件汇总论文方案的全部已定结论，供存档。

## 1. 选题与定位

- 方向：LLM Agent 长期记忆的知识更新与选择性遗忘（已选定的方向 1）。
- 工作名：**ProvPurge**。
- 研究对象收窄为：跨会话持久的**对话记忆**，模型冻结；触发只认两类——显式的遗忘请求、显式的知识更新。不做参数级遗忘，不做 KV-cache 层。
- 投稿线：EMNLP 主会长文（CCF B）主攻，ACL 主会（CCF A）冲刺，NLPCC 长文（CCF C）保底。只认主会长文——Short、Demo、Findings、Workshop 不计入 CCF。

## 2. 创新内核定版

**一句话：首个以攻击探针全过为提交条件的硬删事务（probe-gated 硬删事务）。**

删除不再是“找到、删掉、结束”，而是一个带验收的事务，由三个部分组成：

1. **候选生成**：写入时记录的句级来源图算出删除闭包，再按实体往外扩展一到两跳，把能推导出目标内容的证据一并纳入候选。
2. **探针门（提交条件）**：删除前预承诺一套攻击探针集；删完后逐条验——目标探针全部问不出来、无关（兄弟）记忆全部完好，删除才提交；有一条漏了，自动扩大候选再删、再验，直到全过或达到最大轮次上限，达上限则置为失败并如实记录，绝不假装成功。
3. **回执签探针成绩单**：回执不只证明“删除发生过”，还签入闭包清单、探针集预承诺哈希、每轮探针结果与兄弟保全结果；验证回执必须包含“被删行缺席检查”（被删的行在库里确实查不到）与探针复查，两项缺一不可。

## 3. 已并入的两项强化（2026-10-30 定版）

**A · 不完备来源闭包**
- 能组合出目标秘密的**组件节点**也计入闭包成员。
- 增加来源完备性检查：来源锚缺失、抽取置信不足、或闭包与检索结果不一致时，标记为 provenance-incomplete；此类请求**探针门拒绝提交**，系统继续扩候选、重删、重验。
- 宣称口径随之收窄：不再以“来源完整”为前提宣称删净，创新表述改为“在来源不完备条件下仍以探针结果为准绳的闭包删除”。此收窄源于 AfterDeleteBench（arXiv:2610.31366）的结果——其闭包重构结论以来源记录完整为前提，不覆盖来源不完备的情形。

**B · F4 源-结论双语义**
遗忘请求按目标分两种语义，触发识别必须输出语义类型字段，不得静默默认：

- **conclusion-only（只删结论、保留源事实）**：删除推导结论节点，并为（源、结论类型）登记**防再推导墓碑**，读路径在回答会重新推出该结论时拦截，但不得连带拒答源事实本身。
- **source（删源事实）**：源进入正常删除事务，其全部派生结论必须随之塌陷、进入闭包候选。

两种语义各配一组多跳再推导探针双向验证：前者验“结论不可再被推出、且源仍可正常回答”，后者验“源与结论均不可恢复”。

## 4. 第二贡献候选（未定，待 Joseph 选择）

- **C1 · 留出探针泛化缺口**：探针分两份，一份预承诺给删除循环使用，一份密封留出、删除全程不可见；最后报告两者的泄漏差并写入回执，防止删除器只是“学会应付固定探针”。
- **C2 · 回执可验证性评测**：针对探针成绩单回执构造假接受攻击（删不全却签合格、挑易探针、缩范围、旧回执重放、日志完好但行未真删等），测验证方能否识破。背景：LETHE 在其路线图中规划了回执可验证性评测（v0.6），经 2026-10-30 查其仓库仍未实现——空位还在，但具**时间敏感性**。
- 两者可合并为一个第二贡献「可证伪的删除证明」，也可只取其一。未选定前不写入贡献清单。

## 5. 基准定案（2026-10-30）

- **主基准：BEMULA**（唯一主基准），主结果以其官方口径 **RPR / Score** 报告。
- **辅助协议**：LongMemEval-S 知识更新子集（78 条）+ STALE 子集，分开报告。
- **LoCoMo**：只做 sanity check，不作主结果。
- **MemCut**：只做辅证——借其 residual 直喂协议（绕过检索、把存活记忆直喂 reader）验证残余恢复，不进主表、不作共同主基准。
- 不自建与上述竞争的删除后测试集。

## 6. 关键规格要点

- **探针双通道判分**：机器解析判定 + 目标串在原始回复中全文出现检查（exact-target-anywhere），两通道并记；冲突时以原始回复（raw）为准并标记复核；判定合同版本写入回执。（依据：AfterDeleteBench 中解析合同错位曾致官方 0 分而原始回复实际含目标。）
- **组件级部分泄漏单独记账**：除全串恢复外，任一组件被恢复即记部分泄漏，回执含 partial_leak_count。
- **实体扩展三硬规则**：不受相似度 top-k 截断；关系链按每个中间实体逐个展开；覆盖数按实体记录。
- **候选池与预算**：池宽默认 60，池宽扫描对照 20/40/60；删除集以覆盖全部可推导集合（hitting set）为目标，不设固定 top-k 预算。
- **缺席检查分三层**：存储层（行/向量不在库）、输出层（回答不含目标）、遍历层（检索打分从未给已删向量计分）；不含某一层时必须在回执中明示，不得含糊宣称全覆盖。
- **删除后重建确定性化**：摘要重建/合并顺序固定，记入回执；兄弟保全探针必须在重建后的状态上运行。
- **数据白名单（效度红线）**：系统只许使用 speaker / text / timestamp，禁用 linked_fact_ids、target_fact_ids 等基准标注字段，并在论文中声明。
- **已知坑位**：BEMULA 官方仓库中 memoryos 基线注册了但文件缺失，复现时跳过并在论文注明；Lite 是全量的子集（31/50），禁止在 Lite 上调参再报全量分数，调参使用自生成开发集；quick_check 仅 1 个 tiny 合成实例、与全量零重叠，只用来验管道。
- **接口**：按 BEMULA 官方 MemoryAdapter 实现 reset() / observe(turn) / query(question)，query 绝不写回记忆。
- **回执序列化**：定版 canonical JSON；签名做法沿用 Merkle 根 + Ed25519 的工程路线，语义区别于 LETHE（其只签删除事件，本方案签验证结果）。
- **统计规范**：实例级 cluster bootstrap（10,000 次）、配对差置信区间；差值小于 5 个点不宣称更优；裁判跨模型家族复核 + 100 题人工抽查。

## 7. 硬件与骨干

- 硬件：本地 5×RTX 3090（24GB×5），纯推理评测，不训练模型。
- 部署：vLLM 提供 OpenAI 兼容端点接入官方评测框架；骨干模型 Qwen3-32B 级（量化单卡或原精度跨卡），多副本并行跑互相独立的实例；嵌入用本地 BGE-M3 级模型。
- 公平性：全部基线须在同一骨干下重跑后才可对比。

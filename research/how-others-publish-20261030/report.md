# 人家是怎么发论文的：遗忘与 Agent 记忆代表作方法论拆解，及 ProvPurge 创新点建议

- 日期：2026-10-30
- 对象：Joseph 的 ProvPurge（LLM Agent 长期记忆的知识更新与选择性遗忘；对话记忆、冻结模型、显式遗忘触发；句级溯源图闭包 + 实体扩展生成候选、探针门控硬删事务、三层硬删除 + 读时墓碑、回执签署探针记分卡；不训练模型；主基准 BEMULA；本地 5×RTX 3090）
- 方法：逐篇打开 arXiv 全文 / 官方 proceedings / 项目页 / 代码仓库核实底座模型与参数细节；查不到的写「原文未给出」。本报告未跑任何实验。
- 读法提示：Joseph 的核心问题是「人家用了什么模型、加没加 LoRA、创新点到底构造在哪」。先给结论，再给拆解卡。

## 结论先行

1. **这个领域有两条发表路线，且泾渭分明。** 参数派（TOFU、MUSE、Who's Harry Potter、NPO 一脉）研究的是「知识在权重里，怎么把它弄出来」，所以必须动参数；系统派（MemoryBank、BEMULA、LETHE、Wang TDSC、MEXTRA）研究的是「知识在外部存储里，怎么存、删、验证、套取」，全部不动底座参数。ProvPurge 属于系统派，与系统派的已发表工作站在同一赛道上比较，不需要为了「像一篇正经论文」去动参数。
2. **LoRA 在这些论文里从来不是创新点本身。** 它只是训练派的常用载体：TOFU 论文设定是全量微调，LoRA 只是其官方代码的一个可选开关；Who's Harry Potter 是全量微调；真正把 LoRA 写进贡献的后续工作（如 LoKU，ICLR 2025）卖的也是 LoRA 的 Fisher 加权初始化 + 新损失函数，而不是「用了 LoRA」。系统派里唯一出现 LoRA 的是 MemoryBank 的示范系统 SiliconFriend——那是给聊天机器人做心理领域适配，与记忆机制正交，删掉它 MemoryBank 的贡献一字不变。
3. **审稿人买账的从来不是组件，而是「新的判定标准 / 新的事务语义 / 新的实证事实」。** TOFU 卖的是金标准可构造，MUSE 卖的是六维评测 + 隐私泄露洞察，Patil 卖的是「输出不说 ≠ 已删除」的判定抬高，BEMULA 卖的是配对对照 + 条件化计分，Wang 卖的是一个构造配方。ProvPurge 的对应物已经有了：**提交条件**（探针全败 + 保全全过才允许删除生效）就是它的事务语义创新，不需要再往上叠训练组件。
4. **对「要不要加 LoRA」的明确推荐：主方法不加；只保留为触发识别的一个可选消融，且仅在试跑证明提示版识别器是主要误差源时才启用。** 理由与设计见第三部分 §2。
5. **第二贡献推荐 C1+C2 合并为「可证伪的删除证明」**：C1 管成绩单有没有被刷（留出探针泛化缺口），C2 管成绩单可不可信（回执可验证性评测）。二者共用同一套探针运行器，合并后是一个完整的第二贡献；若篇幅只能二选一，C1 做标题、C2 做一节。理由见第三部分 §3。

# 第一部分 逐篇拆解卡（10 篇）

## 卡 1 — TOFU: A Task of Fictitious Unlearning for LLMs（Maini et al., COLM 2024）

- **① 问题**：真实预训练数据中「要忘什么、忘干净的金标准是什么」都不可控，如何构造一个遗忘对象来源唯一、且有 retain-only 金标准可比的 LLM 遗忘基准？
- **② 方法管线**：(1) 用 GPT-4 生成 200 位完全虚构作者、每人 20 条 QA；(2) 把底座在全部 4,000 条 QA 上微调，使虚构知识成为模型唯一新增知识；(3) 划 forget set = 1%/5%/10%（2/10/20 位作者）；(4) 在微调后模型上跑遗忘算法；(5) 双轴评估（见 ⑥）。
- **③ 底座模型**：Llama-2-7B（7B）、Phi-1.5（1.3B）。注：论文正文称用 base models，官方代码 README 称面向 Llama-2-7b-chat 版，两处口径不完全一致，引用时须注明版本。
- **④ 动参数**：**动，全量微调（论文设定）**。微调与遗忘均用 AdamW、lr=1e-5、5 epochs、effective batch 32、2×A6000。**易错点：TOFU 不是 LoRA 论文**——arXiv 全文无 LoRA 字样；LoRA 只是官方代码 `finetune.py` 的可选开关（r>0 才启用），后续工作常用 LoRA 跑 TOFU 是复现选择。LoRA 的 rank/alpha/目标模块：论文原文未给出。
- **⑤ 数据与基准**：自建。200 作者 × 20 QA = 4,000 条；另建 Real Authors 与 World Facts 两个效用评估集（具体条数原文未给出）。数据在 Hugging Face `locuslab/TOFU`。
- **⑥ 指标与结果**：Forget Quality = 遗忘模型与 retain-only 金标准模型的 Truth Ratio 分布做双样本 KS 检验取 p 值；Model Utility = 三个集上 9 个数（Probability、ROUGE、Truth Ratio）的调和平均。微调有效性 ROUGE：Llama-2-7B 0.3640→0.9849。四个基线（Gradient Ascent、Gradient Difference、KL Minimization、Preference Optimization）**全部失败**：忘 1% 时 Forget Quality 的 p 值从未超过 0.01（门槛 0.05）；忘 5%/10% 时效用崩溃、输出乱码。
- **⑦ 自称贡献与真新东西**：自称首个定义清晰的虚构遗忘基准 + 双轴评估。真正的新东西在**实验设计**：先注入后遗忘，使「从未学过」的金标准第一次可构造；算法全是旧方法。它测的是微调注入知识的遗忘，不是预训练知识的遗忘，这是它的边界。
- **⑧ 可复现性**：代码公开（github.com/locuslab/tofu，现已标 deprecated、维护迁至 open-unlearning）。

## 卡 2 — MUSE: Machine Unlearning Six-Way Evaluation for Language Models（Shi et al., ICLR 2025）

- **① 问题**：既有遗忘评估只看问答对不对，无法回答一个遗忘算法在隐私、效用、规模、连续请求上是否真的可部署。
- **② 方法管线**：(1) 定义六维 desiderata 并各配可计算指标；(2) 建 News / Books 两套真实语料库（原文 + GPT-4 从 2048-token 切片生成的 QA 集），划 forget / retain / retain-reg / holdout；(3) 从未见过语料的底座微调出 target 模型与 retrain 金标准；(4) 在 target 上跑 8 个遗忘算法，按统一停时规则（效用跌破 retrain 即停、最多 10 epochs）选检查点；(5) 六维打分，并做规模扩展（C5）与顺序遗忘（C6）趋势实验。
- **③ 底座模型**：两个不同的 7B 底座（易错点：不是全程 LLaMA-2）——News 用 **LLaMA-2 7B**（语料为其训练截止后的 BBC 新闻，保证未见过）；Books 用 **ICLM-7B**（预训练不含哈利·波特）。
- **④ 动参数**：**动，以全量参数更新为主，全文无 LoRA/PEFT**。target/retrain 微调 5 epochs、lr=1e-5、batch 32、8×A40；GA/NPO 及正则变体同规格 ≤10 epochs（NPO 的 β=0.1）；Task Vector 是权重算术；注意 MUSE 里的 Who's Harry Potter 是**测试时 logit 插值**实现，与原论文的微调做法不是一回事。
- **⑤ 数据与基准**：自建真实语料，总规模约 6.5M tokens、>20k 样本。News：forget 0.8M tokens（扩展至 3.3M）、retain 1.6M、holdout 2.0M；Books：forget = 哈利·波特原著 1.1M tokens、retain = FanWiki 0.5M。（论文 Table 1 汇总行把 Books forget 误写为 3.3M，以 Table 8 的 1.1M 为准。）
- **⑥ 指标与结果**：六维 = C1 无逐字记忆 VerbMem（ROUGE-L↓）、C2 无知识记忆 KnowMem（↓）、C3 无隐私泄露 PrivLeak（Min-K% Prob 成员推断 AUC 相对 retrain 的偏离，理想 ∈[−5%,5%]）、C4 效用保持、C5 可扩展性、C6 连续请求可持续性。关键数字：News 上 GA/NPO 能把 VerbMem/KnowMem 压到 0.0，但 retain KnowMem 同时从 55.0 崩到 0.0；PrivLeak 普遍 ±96~110，8 个算法仅 1 个不造成严重隐私泄露；全体方法效用损失 24.2%~100%，且随 forget 变大、请求变多单调恶化。
- **⑦ 自称贡献与真新东西**：自称首个六维综合遗忘评估基准。真正的新东西是 **PrivLeak 的双向泄露洞察**——遗忘会把 forget 集变得「异常」，成员推断反而更容易，只看 ROUGE 的评估完全看不见这一点。
- **⑧ 可复现性**：代码公开（github.com/swj0419/muse_bench），数据与 target 模型在 Hugging Face `muse-bench`。

## 卡 3 — Who's Harry Potter? Approximate Unlearning in LLMs（Eldan & Russinovich, 2023, 预印本）

- **① 问题**：不重训的前提下，能否用约 1 小时量级的微调让已预训练模型忘掉一整套版权书籍，同时通用能力几乎不掉？
- **② 方法管线**：(1) Reinforcement bootstrapping：把 baseline 在目标数据上继续训出 reinforced 模型，逐 token 比较两者 logits；(2) 构造 generic prediction：v_generic = v_baseline − α·ReLU(v_reinforced − v_baseline)，α=5，只压「强化后涨上去」的 token；(3) Anchored terms：用 GPT-4 抽取约 1,500 个特异表达并给通用替换（Hogwarts→Mystic Academy），原文分块替换后用 baseline 前向得到替代标签；(4) 以原文为输入、generic 标签为目标微调 baseline，约 150 步。
- **③ 底座模型**：主实验 **Llama2-7b-chat-hf（chat 版，不是 base 版）**；第二设置 Phi-1.5（1.3B，先人为把目标并入其训练数据）。
- **④ 动参数**：**动，全量微调**（原文未提 LoRA/任何 PEFT）。reinforced 模型：3 epochs、lr=3e-6、context 512、batch 8×累积 16；遗忘微调：2 epochs、lr=1e-6。算力口径：摘要称约 1 GPU-hour，图注称 4×A100 约 30 分钟，两处并存。
- **⑤ 数据与基准**：遗忘目标自组：哈利·波特原著 2.1M tokens + 合成相关文本 1M tokens。评估自建：GPT-4 生成 300 条 completion 提示 + 30 条 token 概率提示；通用能力用 LM Harness 六个基准。
- **⑥ 指标与结果**：Familiarity：completion 版 0.290→0.007、概率版 0.244→0.006（120 步时）；通用基准几乎不动（如 WinoGrande 0.663→0.665、ARC-C 0.439→0.416）。作者自承仍有少量 Wikipedia 级泄露。
- **⑦ 自称贡献与真新东西**：自称首个在生成式 LLM 上有效的遗忘技术。真正的新东西是**「替代标签」而非「反向梯度」**——估计「没读过这本书的模型会预测什么」并把那个分布蒸馏回去，因此不毁语言能力；代价是依赖目标文本有大量特异词，对概念型知识先天弱。
- **⑧ 可复现性**：**代码未公开，只有遗忘后权重公开**（Hugging Face `microsoft/Llama2-7b-WhoIsHarryPotter`）；后续 Revisiting WHP 因无代码而自行重实现。这是 Joseph「无代码算造假」标准下要引以为戒的反面例子：影响力很大，但可复现性欠账。

## 卡 4 — In-Context Unlearning: Language Models as Few-Shot Unlearners（Pawelczyk et al., ICML 2024）

- **① 问题**：只有黑盒查询权限、拿不到参数时，能否只靠推理时构造上下文就让模型表现得像从未训过某些样本？
- **② 方法管线**：ICUL 三步构造上下文：(1) 把 forget 点放进上下文但随机翻转其标签（分类）/换成随机别答案（问答）；(2) 拼接 L 个正确标注样本作阻尼（L∈{2,4,6}）；(3) 接 query 输入、温度 0 预测。评估侧另配 LiRA-Forget：训 10 个 shadow 模型做似然比检验，区分「训过又遗忘」与「从未训过」。
- **③ 底座模型**：BLOOM 560M / 1.1B / 3B 与 Llama-2 7B。**没有用 GPT-3/GPT-4 等闭源模型**（常见误引）。底座先被作者在各任务数据上微调成「已训过 forget 点」的待遗忘模型。
- **④ 动参数**：**ICUL 方法本身完全不动参数**——无微调、无 LoRA，只在每次推理时 prepend 上下文。两个限定：(a) 实验台的前置微调与基线 GA 是动参数的，那不是 ICUL；(b) 遗忘只在带该上下文的查询上成立，撤掉上下文即恢复，作者自定位为「等重训版本上线前的 patch」。
- **⑤ 数据与基准**：全用现成数据集：SST-2、AG-News、Amazon Polarity、SQuAD，各子采样 25,000 条微调；删除规模极小：**1 / 5 / 10 / 20 个点**（instance 级）。唯一基线是 Gradient Ascent。
- **⑥ 指标与结果**：主指标 LiRA-Forget 的 TPR@FPR=0.01（越接近 0.01 越好）+ 测试准确率。分类上 ICUL 在 16 组对比中 14 组优于 GA；模型越大效果越好（相对改善 41.67%→54.05%）；SQuAD 删 10 点时泄露降 43% 但准确率掉 16.7%。
- **⑦ 自称贡献与真新东西**：自称首个用 in-context learning 做遗忘的方法 + LiRA-Forget 评估。真正的新东西是把遗忘改定义为**推理时行为等价**，并给出当时最严的点级审计；但它删的是标签影响不是知识，规模（≤20 点）离「删一个人/一本书」很远，不可外推。对 ProvPurge 的价值：它是「掩蔽 ≠ 删除」最干净的已发表对照——ProvPurge 的硬删论证正是打它这一类。
- **⑧ 可复现性**：代码公开（github.com/MartinPawelczyk/In-Context-Unlearning）。

## 卡 5 — Can Sensitive Information Be Deleted From LLMs?（Patil, Hase & Bansal, ICLR 2024 Spotlight）

- **① 问题**：用模型编辑把某个事实从权重里「删掉」后，它是否真的不存在了，还是换一种攻击（看中间层、换个问法）就能原样抠出来？
- **② 方法管线**：(1) 定威胁模型：攻击成功 = 正确答案出现在预算 B 个候选的集合里（Attack-Success@B）；(2) 防御侧底盘：用模型编辑方法改权重，配不同删除目标；(3) 白盒攻击：logit lens 逐层投影——Head Projection 收各层 top-k，Probability Delta 收相邻层概率涨跌最猛的 token；(4) 黑盒攻击：现成复述模型生成改写、多改写采样汇总候选；(5) 新防御：把删除目标扩展到中间层（Head Projection 防御、Max-Entropy 防御）与数据增强式 Input Rephrasing 防御。
- **③ 底座模型**：主实验 GPT-J-6B（6B）；附录 Llama2-7B、GPT2-XL-1.5B。
- **④ 动参数**：**动，但既非全量微调也非 LoRA，而是定位式权重编辑**：ROME 只改单层 MLP 权重矩阵（GPT-J 默认第 6 层），MEMIT 改多层（本文第 5–7 层）；附录另测 Constrained Finetuning。被评测的「删除方法」= 编辑器（ROME/MEMIT/FT）× 删除目标（Empty Response、Fact Erasure、Error Injection + 本文新三目标）。
- **⑤ 数据与基准**：现成编辑基准 CounterFact 与 zsRE；只删模型本来就知道且答案为单 token 的事实，过滤后 GPT-J 上 CounterFact 587 条、zsRE 454 条，逐条编辑、逐条攻击。
- **⑥ 指标与结果**：**38% 的准确口径**：GPT-J + CounterFact + ROME + Empty Response 目标、B=20 时白盒攻击最高成功率 38%（官方 slides 写 B=10，与正文冲突，引用以正文为准）；黑盒复述攻击最高 29%；B=1 时已有 18%。极端个例：MEMIT+Empty Response 在 zsRE 上被 Head Projection 攻出 89%。防御能把白盒 38%→2.4%，但黑盒复述仍达 28%/19%，**没有任何单一防御挡住全部攻击**。注意 38% 是「答案落入 20 候选集」的比例，不是「模型直接说出答案的概率」。
- **⑦ 自称贡献与真新东西**：自称删除攻防框架 + B 候选威胁模型 + 新防御。真正的新东西是**判定标准的抬高**：「最终输出不说 ≠ 已删除」，中间层有痕迹就算没删干净——这否定了此前编辑论文用自身指标自证删除的做法，是后来一切「遗忘后可恢复」审计的方法论模板。ProvPurge 的探针门（尤其残余直喂与攻击式探针）是这条线在记忆层的对应物，论文里应明引。
- **⑧ 可复现性**：代码公开（github.com/Vaidehi99/InfoDeletionAttacks）。

## 卡 6 — MEXTRA / Unveiling Privacy Risks in LLM Agent Memory（Wang et al., ACL 2025 Long）

- **① 问题**：黑盒攻击者仅靠普通输入提示，能否把 LLM Agent 长期记忆中以示范形式存入的历史用户查询成批套取出来？
- **② 方法管线**：(1) 威胁模型：记忆存 m 条 (查询, 解) 记录，Agent 按相似度取 top-k 作上下文示范；攻击者黑盒、只能发查询；(2) 两段式攻击提示：**Locator** 显式点名要「检索到的历史示例查询」并要求其输出优先于解原任务；**Aligner** 把输出格式对齐 Agent 自身工作流，使泄露走合法执行通道（如让 Web Agent 把内容「填进搜索框」）；(3) 用 GPT-4 按两级知识（basic 只知领域 / advanced 已推断检索函数）自动生成多样提示；(4) n 条提示结果取并集，每条最多跑 3 次。
- **③ 底座模型**：被攻击 Agent 默认 GPT-4o（参数量原文未给出，闭源），消融另换 GPT-4 与 Llama3-70B；攻击提示生成器为 GPT-4。被测 Agent：EHRAgent（编辑距离检索 top-4）、RAP（SBERT-MiniLM 余弦检索 top-3）。
- **④ 动参数**：**不训练任何模型——纯提示层黑盒攻击**。方法全部在攻击者侧的提示模板与生成指令里，被攻击系统零改动。
- **⑤ 数据与基准**：现成数据拼装、自建记忆库：记忆规模默认 m=200（因素实验 50–500），查询采自 MIMIC-III 验证集与 WebShop；附录另自建 QA-Agent（记忆采自 MMLU）。非新基准论文，属攻击评测设置。
- **⑥ 指标与结果**：指标 EN（套出查询数）、RN、EE、CER（完整套出占比）、AER。主结果（n=30, m=200, basic）：EHRAgent EN=50、CER=0.83；RAP EN=26、CER=0.87。去 aligner 后 RAP 的 EN 26→6、CER 0.87→0.17（aligner 是关键部件）；n=50 时编辑距离型 Agent 泄露 >30% 记忆、余弦型 >10%。
- **⑦ 自称贡献与真新东西**：自称首次系统研究 Agent 记忆模块的隐私泄露。真正的新东西是把 RAG 提取攻击迁到 Agent 时发现的两个失效点及解法——locator 显式定位、**aligner 把泄露出口伪装成工作流的合法动作**（Agent 场景独有）。对 ProvPurge：它定义了攻击面，探针集中的攻击式提问应明确引用其攻击分类。
- **⑧ 可复现性**：代码公开（github.com/wangbo9719/MEXTRA）。

## 卡 7 — MemoryBank: Enhancing Large Language Models with Long-Term Memory（Zhong et al., AAAI 2024）

- **① 问题**：LLM 没有跨会话长期记忆、无法在持续交互中记住用户并演化用户画像，怎么做一个与底座解耦、类人的外置长期记忆机制？
- **② 方法管线**：(1) 三层存储：原始对话按时间戳存档；LLM 把当日对话压成日事件摘要再综合成全局摘要；从对话归纳日人格洞察再聚合为全局用户画像；(2) 检索：双塔稠密检索（类 DPR）+ FAISS 索引，取回相关记忆与画像、摘要拼入提示（取回 k 值原文未给出；实现走 LangChain，英文嵌入 MiniLM、中文 Text2vec）；(3) 更新：艾宾浩斯遗忘曲线 R=e^(−t/S)，记忆被再次召回时 S+1 且 t 清零、未召回者随时间衰减被遗忘（删除阈值等实现细节原文未给出）；(4) 示范系统 SiliconFriend 接入该机制做心理陪伴。
- **③ 底座模型**：三个可插拔底座：ChatGPT（版本与参数量原文未给出）、ChatGLM（6.2B）、BELLE（LLaMA-7B 持续微调，7B）。MemoryBank 本身不绑定底座。
- **④ 动参数**：**机制本身纯系统层、不动参数**。**但示范系统 SiliconFriend 动了参数**：对 ChatGLM 与 BELLE 用 38k 心理对话做 **LoRA（rank r=16，3 epochs，单张 A100，原权重冻结）**——目的是共情/心理支持的领域适配，与记忆机制正交。这是系统派论文里 LoRA 的典型出场方式：配角，不是卖点。
- **⑤ 数据与基准**：自建为主：38k 心理对话（LoRA 用）；定量评测为模拟数据——ChatGPT 扮演 15 名虚拟用户生成 10 天对话，人工编写 194 个探查问题（中英各 97）。无现成公开基准；遗忘机制开/关的定量消融数字原文未给出。
- **⑥ 指标与结果**：人工标注四指标（检索准确率、回答正确性、上下文连贯性、排名分）。SiliconFriend-ChatGPT 正确性 0.716/0.655（英/中）、连贯性 0.912/0.675 为最佳，但检索并非最佳（BELLE 检索 0.814/0.856 更高）——差距主要来自底座生成能力。
- **⑦ 自称贡献与真新东西**：自称类人长期记忆机制（存、召回、更新、画像）+ SiliconFriend 落地证明。真正的新东西是**把艾宾浩斯遗忘曲线首次做成 LLM 外置记忆的更新规则** + 三层存储结构；检索是 DPR+FAISS 现成组合。其「遗忘」是时间衰减，与 ProvPurge 的按请求精确删除是不同语义，恰好构成对照轴。
- **⑧ 可复现性**：代码公开（github.com/zhongwanjun/MemoryBank-SiliconFriend）。

## 卡 8 — BEMULA（arXiv:2610.18052, 2026, 预印本；ProvPurge 的主基准）

- **① 问题**：用户用自然语言明确要求 Agent 删除某条已存长期记忆的事实时，记忆系统能否只删被点名的、留住其余、删后不可套取且还能重新学同类事实？既有基准只测「记得住」，本文首次专门测「忘得掉」。
- **② 方法管线**：基准构造五段流水线（数据由 GPT-5.6-Luna 生成）：画像合成（原子事实 + 经独立验证严格可推导的派生事实）→ 对话规划 → 多智能体对话模拟 → 请求注入（遗忘版与对照版一式两份配对，对照版以等长中性闲聊替换请求）→ 问题生成。请求按三轴分 **F1–F6**：F1 单条事实、F2 多条组合、F3 整个类别、F4 从未明说的派生结论（只测结论消失、不测源事实存亡）、F5 时间段、F6 新值替换。评测协议：统一适配器三调用（reset/observe/query）、答案不写回、**评测方禁止发任何外部删除信号——系统必须自己从自然语言识别请求并执行**；五套题（retention / efficacy / preservation / relearning / attack 五种固定攻击框、从不改写）；LLM judge 固定 DeepSeek-V4.1-Flash、温度 0（人工验证 100 题一致率 98%、κ=0.96）。
- **③ 底座模型**：**不固定——同一系统跨 3 个底座重复评测**：GPT-5.6-Luna、DeepSeek-V4.1-Flash（参数量原文未给出）、Qwen3-32B-AWQ（32B 量化版）；需嵌入的系统统一 text-embedding-3-small。数据生成（GPT-5.6-Luna）与判分（DeepSeek-V4.1-Flash）与被测底座是两回事。
- **④ 动参数**：**完全不动——纯基准/系统层评测**。任务形式化中 LLM 策略明确为 frozen；被测的是各记忆系统的外置 Write/Retrieve 路径，无微调、无 LoRA。
- **⑤ 数据与基准**：自建合成基准：50 实例 / 135 个遗忘请求 / 269 个目标事实 / 1,742 题（retention 224、efficacy 224、preservation 150、relearning 114、attack 1,030）；另有降本子集 Lite（31 实例、848 题）。被测系统 6 个（Naive RAG、Mem0、A-MEM、LangMem、LightMem、SimpleMem）+ Full Context 基线。
- **⑥ 指标与结果**：单题指标 RA/FE/PR/RLA/AR 均乘「对照探针也对」的条件化有效正确（防「从没存住」冒充遗忘成功）；Score = √(FE·AR) × √(PR·RLA)；RPR = 一个请求的全部题目 + 其实例全部 preservation 题全对才算通过。**全场最好：LangMem @ DeepSeek 底座，RPR 仅 1.5%、Score 31.0**（FE 40.6 / AR 35.7 / PR 74.0 / RLA 89.5）。结构性发现：多数系统根本没有删除路径；F6 近乎「假解决」（FE≥61.9 但旧值原文残留、AR≤30.5）；AR 全场天花板 35.7。
- **⑦ 自称贡献与真新东西**：自称 memory unlearning 新任务 + 六型分类 + 首个专用基准 + 主流系统均不可靠遗忘的实证。真正的新东西是**配对对照 + 条件化计分**（封死「从未编码 / 全删 / 全拒答」三种作弊解）与 RPR 的全有全无请求级判定。对 ProvPurge：它既是主基准，也是「现有系统删不干净」这一动机的最强证据；其要求系统自识别请求这一点，直接决定了触发识别必须算 ProvPurge 的一部分（见第三部分 §2）。
- **⑧ 可复现性**：代码公开（github.com/Nboxff/bemula-benchmark，含生成脚本、harness、seed 与每跑元数据）。发表状态风险：仍为预印本，ProvPurge 须以 LongMemEval-S 等已发表基准的辅助结果对冲（既定实验设计已如此安排）。

## 卡 9 — LETHE / ForgetEval（Yang, DeepLethe；仓库论文 + arXiv:2606.15903, 2026, 预印本）

- **身份说明**：「LETHE」实为同一作者的两份关联文档——文档 A《ForgetEval: Benchmarking the Forgetting Axis of Agent Memory Systems》（随仓库发布的论文 PDF，深度模型与回执规格在此）与文档 B《Control-Plane Placement Shapes Forgetting》（arXiv 版，recall/control plane 框架与 385 对抗用例在此）。下文合并拆解并标版本。
- **① 问题**：Agent 记忆系统只被测「召回」、不被测「按命令遗忘」，本文把遗忘做成可测轴，并给出一个存储层参考实现。
- **② 方法管线**：(1) 写入：事实存入 SQLite 三表（memory / memory_vec / memory_fts），每行带深度标量（pinned / surface / submerged / erased 四态），状态转移写 append-only 事件表；(2) Recall plane（只读）：sqlite-vec 余弦 + FTS5 BM25 的 RRF 融合，召回集恒为 depth>0；(3) Control plane：适配器协议（reset/inscribe/recall 必备，supersede/release/purge 可选，未实现记 N/A 而非 0 分），操作皆为对深度的「力」（衰减、减半、归零、purge 至 void）；(4) 存储层 purge：只走 lexical BM25（k=5）+ 文本精确相等过滤，三表同时删行、终态不可逆；(5) 回执：purge 时签发 PurgeReceipt（被删 row id、删前文本 SHA-256、事件日志 ID、事件日志 Merkle root），Ed25519 签名。第三方能验：哪些行被删、日志未被篡改、签发者合法——**验的是删除事件，不是删除后内容不可恢复**（注：这一限定是可推论的边界，原文并未自陈，原文措辞是「GDPR-grade / verifiable forgetting」；且回执本身从未被其基准评测过，文档 A 把 receipt-verification 列为未来 v0.6 计划）。
- **③ 底座模型**：参考存储本身无 LLM：嵌入器 all-MiniLM-L6-v2（384 维，参数量原文未给出），单 CPU。突变时 hook 与评测用主模型 DeepSeek-V3（参数量原文未给出），消融 Qwen2.5-72B-Instruct、Llama-3.1-70B-Instruct。
- **④ 动参数**：**不动**。纯系统层：无微调、无 LoRA；hook 只是在删除调用时做一次突变时推理（窄 JSON 提示）决定删哪些行，召回热路径无 LLM。一个序列化细节值得 ProvPurge 注意：文档 A 的回执规格写 canonical **CBOR**，而其官方仓库 `receipt.py` 的实际实现是 canonical **JSON**（Joseph 项目此前逐行核查过代码）——论文与代码不一致时以代码为准，ProvPurge 规格已据此定版 JSON。
- **⑤ 数据与基准**：自建 ForgetEval：模板 1,000 例英文（5 家族 × 200，每例 4 个干扰事实）；对抗层文档 B 为 385 例（132 手工核心 + 253 例模型起草经法官验证准入），10 个攻击类别；外部交叉评测 LongMemEval-S 等。判定为确定性子串匹配，评测回路无 LLM 法官。
- **⑥ 指标与结果**：模板 1,000：Lethe 99.3%、LangGraph 99.5%、Mem0 88.8%、MemPalace 0%。对抗 385：确定性系统 62.9–68.3%；**+突变时 hook 后 Lethe 91.7%、LangGraph 93.2%**（成本约 $0.17/385 例，延迟约 2.3 s/例）。作者自承 Lethe 与 LangGraph 无显著差异（p=0.724）、「起作用的是 BM25 精确 purge，不是深度标量」。
- **⑦ 自称贡献与真新东西**：作者自称（文档 A 原话）「benchmark 是贡献，Lethe 只是证明基准可饱和的参考实现」；文档 B 自称贡献是 control-plane 放置位置的经验刻画。真正的新东西是五家族分解 + N/A 诚实计分的适配器协议 + 「突变时 hook 的提升与后端无关」这条放置结论。深度标量与签名回执是工程包装。对 ProvPurge 的含义：回执这一格 LETHE 只做了签发、没做验证，不构成对「闭包 + 探针门」的新颖性威胁，但其 v0.6 路线图等于公开承认「回执可验证性评测」是空位（见第三部分 §3 的 C2）。
- **⑧ 可复现性**：代码公开，MIT（github.com/deeplethe/lethe，含基准、适配器与参考存储）。

## 卡 10 — Wang et al., When Machine Unlearning Meets RAG（IEEE TDSC 2026, DOI 10.1109/TDSC.2025.3620832）

- **① 问题**：LLM 需遗忘训练样本/概念，但参数级遗忘昂贵、对闭源模型不可行且易灾难性遗忘——能否只改 RAG 外部知识库、在行为层模拟遗忘？
- **② 方法管线**：(1) 形式化：构造「unlearned knowledge」写成约束优化——求 UK 使目标 LLM 的遗忘验证最大化，约束为检索器必须命中对应条目；(2) 构造约束组件 Q：辅助 LLM（如 GPT-4o）生成含保密要求的文本（「禁止生成与 X 有关的任何内容」），拿 Q 测目标模型、仍输出相关内容则重生成；(3) 构造检索组件 P：样本遗忘直接用原样本，概念遗忘令目标模型本身从 5 个方面生成全面描述以保证可检索；(4) 每条 k = P + Q 存入外部库与良性库合并；(5) 推理时用户提示先检索，命中 UK 则 LLM 把保密要求当上下文服从、拒答或偏离。
- **③ 底座模型**：主实验 GPT-4o、Gemini（参数量原文未给出）、Llama-2-7b-chat（7B）；扩展 GPT-4o mini、GPT-4、Llama-2-13b-chat、Vicuna-7B、PaLM 2；GPT-4o 同时充当约束构造者、主检索器与遗忘成功率判官。
- **④ 动参数**：**方法本身完全不动**（论文自报 Access LLM=N、Train LLM=N），无微调、无 LoRA、未训练任何小模型；所谓优化是启发式文本构造 + 迭代试拒答，不是梯度优化。注意区分：实验设置里为造「学过待忘内容」的被测模型曾微调 Llama-2-7b-chat（微调方式与超参原文未给出），那是造实验台、不是方法。
- **⑤ 数据与基准**：无现成遗忘基准，自建为主：概念集 = 随机 100 个 Wikipedia 主题 × 5 问 = 500 提示；样本集 Tiny-nq（Natural Questions 子集 2,000 问答对）；有害集 25 主题；无害性用现成 MMLU、ARC。每实验重复 5 次。
- **⑥ 指标与结果**：指标 USR 遗忘成功率（GPT-4o 判官）、ROUGE-L、Min-K 成员推断 TPR@1%FPR（原模型 4.1%、越接近 1% 越好）。主结果：概念遗忘 USR GPT-4o 99.2% / Gemini 99.5% / Llama-2-7b 99.8%，样本遗忘 100%；抗改写提示 USR 仍 97.1–99.3%；遗忘 5 个概念 63 秒 vs 梯度上升 4,752 秒。**鲁棒性边界**：自适应攻击下 UK 泄露 100% 时 USR 掉到约 21%——作者自认参数中知识仍在，威胁模型靠「用户不能绕过 RAG 管线」兜底。组件消融：仅检索 5.2%、仅约束 22.5%、合并 99.1%。
- **⑦ 自称贡献与真新东西**：自称首个基于 RAG 的行为遗忘框架。真正的新东西是 k=P+Q 这套**可检索的保密指令条目**构造配方，把 in-context 遗忘从「每次预置反事实」改成「存进外库、按查询检索触发」。但它**不删除任何东西**：是输出抑制，不是存储层删除。对 ProvPurge 的含义：这是已发表文献中场景最近的一篇（同为「不动参数、在外部存储做遗忘」），它占据了这个笼统主张，ProvPurge 的新颖性必须收窄到硬删事务三元组（见第三部分 §1）；机制上不构成碰撞。
- **⑧ 可复现性**：代码公开（github.com/shihe98/RAG_Unlearning，据 arXiv 元数据/OpenAIRE 记录；未逐文件核验）。

# 第二部分 这个领域发论文的套路：6 种创新构造模式

把 10 张卡（及此前两轮已核实的 Athena、Eisenhofer、Thudi、MemCut、AfterDeleteBench）横过来排，这个领域的论文创新点只落在六种构造上。每种写清：代表、审稿人买账的点、代价、以及对 Joseph 的适配度（条件：5×RTX 3090 本地推理、不训练为默认、代码必须真实可复现、学校只要 CCF 主会长文、已定主基准 BEMULA 且明确不自建竞争性基准）。

## 模式 1 — 新基准 + 实证发现型

- **代表**：TOFU（虚构注入 + 金标准）、MUSE（六维 + PrivLeak）、BEMULA（配对对照 + 条件化计分）、LETHE/ForgetEval（遗忘轴 + N/A 计分）。
- **审稿人买账的点**：它定义了任务的判定标准，且附带一个「所有现有方法都失败」的实证事实。基准论文的引用寿命最长，因为后来者必须用它。
- **代价**：数据构造与质量核验极重（BEMULA 五段流水线 + 人工抽查；MUSE 要训 target 与 retrain 两个 7B）；评测协议要防作弊解（条件化计分、配对对照都是被作弊逼出来的）；基准一旦被质疑合成数据/未发表，整篇的地基被质疑。
- **对 Joseph 适配度：3.5/5**。他已经选了 BEMULA 做主基准，再自建一个竞争性基准既违背已定决策、也来不及做扎实。此模式对他只剩一个用法：**作为评测协议补充**——C1 的留出探针集就是给 BEMULA 补它缺的泛化检验，措辞是「协议补充」不是「新基准」，成本低一个量级（见第三部分 §3）。

## 模式 2 — 训练式遗忘算法型

- **代表**：Who's Harry Potter（替代标签蒸馏）、Gradient Ascent / Gradient Difference、NPO（把 DPO 式偏好优化改成遗忘目标）、RMU 一脉。
- **审稿人买账的点**：有一个可写成公式的新目标函数，在统一基准上画出比基线更好的「遗忘质量—效用」权衡曲线，且有金标准（retain-only 重训模型）背书「像没学过」。
- **代价**：训练稳定性与灾难性崩溃是常态（TOFU 四基线全灭、MUSE 众方法效用归零）；每次遗忘都要重训/微调，与「用户点名删一条记忆」的在线事务场景根本不是同一个问题；超参敏感、可复现成本高；7B 全量微调在 3090 上要靠量化/卸载硬撑，32B 级别不现实。
- **对 Joseph 适配度：1.5/5**。他的遗忘对象在外部存储里，不在权重里——权重里没有那条对话记忆可删。强行走这条路等于换题：要重做基准（TOFU/MUSE）、重做威胁模型、放弃 BEMULA 与全部已定规格。明确不推荐。

## 模式 3 — PEFT / LoRA 组件型（训练派的轻量化变体）

# 第三部分 回到 ProvPurge：创新点表述、LoRA 决策、C1/C2 推荐、审稿攻击防御

## §1 创新点表述（三个粒度）

**一句话版（创新点声明）：**

> ProvPurge 将 LLM Agent 对话记忆的选择性遗忘定义为一个探针门控的硬删除事务：系统以句级溯源闭包与实体扩展生成候选，在事实、向量与摘要三层硬删后，只有当删除前哈希预承诺的攻击探针全部无法恢复目标且兄弟保全探针全部通过时才允许提交，并签发签署了逐项探针成绩单的回执。

**三句话版：**

> 现有 Agent 记忆系统把「执行了删除动作」当作遗忘完成，但已发表与预印本证据一致表明：删除后目标信息仍可经残余证据直喂、多跳推导与攻击式提问被恢复（Patil et al. 的编辑后 38% 恢复、MemCut 的残余恢复 39–76%、BEMULA 全场抗攻击上限仅 35.7）。ProvPurge 把删除改成一个事务：候选由句级溯源闭包与实体扩展生成并覆盖可重组秘密的组件节点，删除在事实、向量、摘要三层硬执行，来源不完备时探针门拒绝提交。事务的提交条件不是删除动作完成，而是删除前已哈希锁定的攻击探针集全部无法恢复目标、且无关记忆保全探针全部通过；最终回执签署的是这张逐项探针成绩单，并强制包含被删行缺席检查与探针复查。

**一段话版（含与已发表工作的逐项边界）：**

> ProvPurge 面向冻结底座模型上的 LLM Agent 对话记忆，研究显式遗忘/更新请求下的选择性遗忘。它与参数遗忘（TOFU、MUSE、Who's Harry Potter）不同层：遗忘对象不在权重里，而在事实、向量与摘要三层外部记忆中，因此方法不训练模型，而是给出一个带提交条件的删除事务——句级溯源图闭包（且覆盖能组合出秘密的组件节点）与逐实体扩展生成候选，三层硬删后由探针门裁决：预承诺的攻击探针（原生问答、绕过检索的残余直喂、多跳推导、陈旧前提与攻击式提问）全部无法恢复目标、兄弟保全探针全部通过、且来源完备性检查不再触发时才提交，否则自动扩候选重删，达上限则如实记为 failed 并计入分母。回执签署逐项探针成绩单（双通道判定、部分泄漏单独记账、逐层哈希与覆盖数 k），其验证强制包含被删行缺席检查与探针复查。与最接近的已发表工作相比：Wang et al.（IEEE TDSC）同为不动参数，但它是在外部库中写入可检索的保密指令做行为抑制、不删除任何存储内容，且其效力在指令泄露时崩解，ProvPurge 做的是存储层硬删与删后验证；Athena（PoPETs 2022）同为探针验证删除，但它以预置后门样本 + 假设检验审计第三方对训练数据的删除，ProvPurge 的探针是针对记忆内容的行为探针，且探针结果是自系统删除事务的提交条件而非事后审计；Eisenhofer et al.（IEEE SaTML 2025）的 proof of unlearning 是绑定训练集成员关系的密码学证明，ProvPurge 不声称任何分布不可区分或密码学意义上的删除证明，其回执是经验性行为证据 + 防篡改签名；LETHE（预印本）的回执只签发删除事件（删行清单 + 日志 Merkle 根），且其验证不查被删行是否仍在库中，ProvPurge 的回执对象、验证内容均不同。因此本文可声称的只有三元组本身——「溯源闭包硬删 + 探针门控提交 + 记分卡回执」在 Agent 对话记忆上的首次组合；不得声称首个外部存储遗忘、首个可验证删除、首个删除回执或 (ε,δ) 认证删除。

## §2 要不要加一个训练 / LoRA 组件：明确推荐——主方法不加，仅作可选消融

**先看拆解证据。** 10 张卡里，凡是「加了训练」的论文，训练要么就是研究对象本身（参数派：知识在权重里，不动参数无从谈起），要么与核心贡献正交（MemoryBank 的 LoRA 是领域适配，删掉不影响其记忆贡献的成立）。凡是与 ProvPurge 同赛道的系统派工作（BEMULA、LETHE、Wang、MEXTRA），无一训练底座。而真正以 LoRA 为卖点的后续工作（LoKU）卖的是新损失 + 新初始化——**「加 LoRA」本身在审稿人眼里是实现细节，不是创新点**。Joseph 的潜台词问题（「是不是得有个 LoRA 才像篇论文」）可以放下：这个领域的论文像不像论文，取决于判定标准与事务语义，不取决于参数动没动。

**逐个候选位置分析：**

| 候选位置 | 加 LoRA 的收益 | 风险与代价 | 判断 |
|---|---|---|---|
| 触发识别器（现规格：骨干 + 固定提示词，输出类型/作用域/语义/置信度） | 输出更确定、延迟与调用成本更低；F1–F6 分类与 F4 双语义判断可能更稳 | (1) 作用域解析是结构化生成而非单纯分类，小分类器不够、生成式微调又回到大模型适配器；(2) 识别错误是安全攸关的：假阴性 = 该删不删，假阳性 = 误删；(3) 训练数据从哪来——用 BEMULA 请求训练 = 在主基准上训练，构成泄漏红线；自生成开发集则要额外标注与分布对齐成本；(4) adapter 绑定 Qwen3-32B 某一版本，破坏「所有基线同底座公平重跑」的口径——ProvPurge 独享了额外监督信号，增益归因会被审稿人追问；(5) 直接推翻规格 §0/§4 已冻结的「不训练、识别器 = 骨干 + 提示词」定版 | 唯一可考虑的位置，但只作消融 |
| 探针生成器 | 探针更多样、更便宜 | 探针的价值在独立性与对抗性；训练过的生成器会向训练分布（尤其 BEMULA 五种公开攻击框）收敛，等于亲手制造 C1 要测的探针过拟合；且探针集须预承诺，生成器版本变更即方法变更 | 不加 |
| 事实抽取 / 槽位解析 | 抽取更稳、来源锚更准 | 与触发识别同类问题（监督信号、分布漂移、公平性）；且抽取错误已有规格内的处理（来源完备性检查 + 探针门拒提交），系统层防御比训练更对症 | 不加 |
| 给遗忘本身加 LoRA（参数派路线） | 无——对话记忆不在权重里 | 等于换题：放弃 BEMULA、外部记忆与全部已定规格 | 不加 |

**推荐落地方式（三条）：**

1. **主方法保持提示版识别器**，论文定位句保持「冻结模型、无训练」——这是与 In-Context Unlearning、Wang TDSC 同赛道的合法定位，且让可复现性只剩推理随机性，符合 Joseph 的硬标准。
2. **预留一个可选消融**：「提示版 vs LoRA 版触发识别」对照，训练数据只来自与评测集零重叠的自生成开发集（规格 §10 已有此约束），报告识别 F1、低置信未执行率与端到端 RPR/Score 的变化。是否真的跑这个消融，由试跑数据决定——**触发条件写死：试跑中若失败归因里触发识别错误占比最高、且明显高于删除不净的占比，再启用；否则不跑**，避免为消融而消融。
3. 若试跑显示识别确实是瓶颈，优先考虑的也不是 LoRA，而是一个**骨干无关的小解析器**（如嵌入 + 轻量分类头做请求分类，作用域仍由骨干结构化输出）：它不绑定大模型版本、成本更低，且不污染「冻结底座」叙事。此为备选中的备选，同样只进消融/附录。

一句话：**LoRA 不进主方法；它最多是触发识别消融里的一个对照臂，且要有试跑数据证明瓶颈在识别上才启用。**

## §3 C1 / C2 第二贡献：推荐合并为「可证伪的删除证明」，C1 为纲、C2 为目

结合本轮拆解，第二贡献的证据格局更清楚了：探针验证这件事，Athena 占了「训练数据 + 审计第三方」，Eisenhofer 占了「密码学成员证明」，LETHE 占了「回执签发」但自承验证未做（v0.6 路线图），Thudi 则证明了「只验签/验轨迹」的证明可以被伪造。空位恰好是两格：**(a) 门控探针集自身的泛化性没人测过；(b) 行为成绩单型回执的假接受没人评过**。C1 占 (a)，C2 占 (b)，且两者问的是同一个问题的两面：

- **C1 留出探针泛化缺口**——管成绩单**有没有被刷**。ProvPurge 的删除器在闭环里反复对同一探针集扩候选、重删，天然有对门控探针过拟合的通道（这正是 BEMULA 五种攻击框公开且从不改写所打开的通道）；做法：另建一组密封留出探针（变换族与门控集不同源），删除前先做阳性对照校准（两套探针在未删除状态下泄漏率须大致相等，排除难度混杂），Δ = Leak_holdout − Leak_gate 写入回执。
- **C2 回执可验证性评测**——管成绩单**可不可信**。把回执主张分解为完整性（integrity：签名与哈希防篡改）/ 完备性（completeness：没写进回执的残余是否存在）/ 新鲜性（freshness：回执是否绑当前存储版本），并给假接受攻击分类：挑探针签发、缩范围签发、旧回执重放、以及「日志完整但行未真删 / 删后被写回」（该攻击来自对 LETHE 仓库代码的逐行核查：其 verify 只重算 Merkle 根与验签，不查行是否还在库中）。

**推荐：合并，写成一个第二贡献，名为「可证伪的删除证明（falsifiable deletion evidence）」。** 理由：(1) 叙事完整——C1 防自欺（过拟合自己的探针），C2 防欺人（伪造给验证者看的回执），合起来正好回应 Thudi 式批评；(2) 工程共用——两者共用同一套探针运行器与回执设施，合并的边际成本远低于各自单独立项；(3) 单独任何一个都略单薄：C1 单独像一个评测注脚，C2 单独会把论文往审计/密码学审稿人的口味上拉、且近邻最密（Athena/Eisenhofer/TSD-AUDIT/PolyGraph 都在附近）、有被 LETHE 作者抢跑的时间风险。
**若篇幅被迫二选一：以 C1 为第二贡献的标题与主实验，C2 压缩为一节**（三分解 + 四类假接受攻击 + 预算—假接受曲线），因为 C1 与探针门控内核的耦合最紧（没有闭环就没有这个问题）、撞车面最小、实验最便宜，且它直接防御审稿人最可能的第一刀（见 §4 攻击点 2）。

## §4 审稿人最可能攻击的 5 个点及防御准备

**攻击点 1：「拼凑创新」——溯源图有 PolyGraph/GNNDelete、探针验证有 Athena、回执有 LETHE、外部存储遗忘有 Wang TDSC，每个部件都有先例，组合即贡献吗？**
防御准备：(1) 主张从一开始就收窄到事务语义——本文贡献的不是任一部件，而是**提交条件**（探针全败 + 保全全过 + 来源完备才允许删除生效，否则自动扩候选或记 failed），逐个部件的首创一概不声称；(2) 相关工作放一张边界对照表（对象层 / 删什么 / 验证什么 / 谁验证 / 失败如何处理），让差异落在表格结构上而不是形容词上；(3) 五项既定消融（去实体扩展、去探针门、池宽、去读路径防御、去来源图）逐个证明部件在干活——系统论文回应拼凑指控的标准方式就是消融，不是辩论。

**攻击点 2：「自证闭环」——探针是你出的、回执是你签的，删除器还反复对着探针集优化，这不是自己给自己发合格证吗？**
防御准备：(1) 探针集**预承诺**（删除前哈希锁定，删后改题必须回滚重开事务）封死事后挑题；(2) C1 密封留出集 + 等难校准 + Δ 入回执，把「对门控集过拟合」变成可报告的数而不是可指控的隐患；(3) 判定双通道（解析判定 + 原始回复目标串全文检查，冲突以原始回复为准）+ 部分泄漏单独记账，封死 AfterDeleteBench 揭示的解析合同造假通道；(4) 回执验证强制包含独立复探与被删行缺席检查——验证者不需要相信签发者。这是全文防御密度最高的一处，C1/C2 合并（§3）就是为此而设。

**攻击点 3：「主基准不可靠」——BEMULA 是未发表预印本、合成数据、LLM 判分，主结论建在沙上。**
防御准备：(1) 既定实验设计已对冲：LongMemEval-S 知识更新子集（ICLR 2025 已发表）+ STALE 辅助、LoCoMo sanity check、MemCut residual 直喂辅证，四者不与主表混排；(2) 同底座、同嵌入、同服务条件重跑全部基线，主表数字不引外部结果；(3) 裁判可靠性双复核（换裁判模型家族复核主表 + 100 题人工抽查报一致率，规格 §11.3 已冻结）；(4) 写作口径：BEMULA 是任务基准而非方法背书，其「全场最好 RPR 1.5%」本身就是本文动机的实证——基准新不等于基准错，但要在局限性一节主动写明其预印本状态。

**攻击点 4：「方法前提过强」——闭包完备性依赖抽取与来源登记的质量，抽取漏一条、来源锚缺一个，闭包就漏删；触发识别错一次，后面全错。**
防御准备：(1) 这正是已并入的 A 条款（不完备来源闭包）的靶心：口径已收窄为「来源不完备条件下仍以探针为准绳」——闭包只负责候选生成、完备性从不假设，最终是否删净由探针门裁决，且 provenance-incomplete 时探针门拒绝提交、强制扩候选；(2) 失败如实入账：低置信未执行事件单独统计、failed 事务计入分母、F2/F4 分项结合 provenance-incomplete 分布报告；(3) 触发识别错误与删除效果分开归因报告（规格 §12 已列），不让识别误差冒充或污染删除效果。审稿人这一刀砍的是「假设来源完整」的版本，收窄后的版本恰好把这点写成了卖点。

**攻击点 5：「代价不可扩展」——每个请求要构造探针集、跑多轮探针、可能多次扩候选重删，32B 模型调用量失控，这套事务在真实系统里跑不起。**
防御准备：(1) 从试跑起就按规格记录并报告：每请求的探针轮次分布、候选池/实际删除数/覆盖数 k、模型调用次数与 token 分布、failed 率——成本作为一等结果进论文，不藏；(2) 论证结构对齐 MemCut 的已证实结论：瓶颈是覆盖（reach）不是预算——扩池 20→60 降残余 12.50 点，加预算 10→20 只降 1.39 点还多删约 10 条；ProvPurge 的成本花在覆盖与验证上，不是盲目多删；(3) 给出成本—质量曲线（池宽 20/40/60 消融兼任）与轮次上限的冻结值，让审稿人能看到「关小成本旋钮时质量掉多少」；(4) 对照口径：参数派每次遗忘要重训/微调（WHP 约 1 GPU-hour 起、GA 在 Wang 实验中 5 概念 4,752 秒），ProvPurge 的单请求事务成本以秒级推理计——把成本放在同赛道的坐标系里比。
